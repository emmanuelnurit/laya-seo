*Scénarios F2/F3 (palier) et le nouveau scénario opt-in (§6.3 du plan), portés par MYO-470/MYO-471. Repli sur F1+F6 — voir §6.*

**Déroulé pas à pas.**
1. Ouvrir la boutique en **session anonyme neuve** (fenêtre de navigation privée — un panier déjà utilisé désactive le message de bienvenue).
2. Ajouter une chaise au panier (catalogue démo, produit au choix hors `PROD006`/`PROD019` réservés aux actes 3/4).
3. Le widget de chat propose : **« Votre panier vous ouvre droit à −10 % sur cette commande. Je vous envoie le code ? »**
4. Saisir un e-mail de la **boîte de démo préparée** (jamais un service de mail public — voir §6), cocher la case **non pré-cochée**, valider.
5. Ouvrir la boîte de démo, montrer le mail reçu avec le code.
6. Revenir sur la boutique, appliquer le code **en un clic** — l'agent rejoue l'événement coupon natif Thelia (`COUPON_CONSUME`), **pas un contournement**. Montrer la ligne de réduction dans le panier.
7. **Le geste qui vend** : fermer le widget de chat. Rouvrir une page, changer de produit, essayer de relancer une conversation. **Rien ne revient de la session.** Le dire explicitement : *« C'est ce moment-là qui vend, pas la fenêtre elle-même. »*

**Ce qu'on montre.** L'offre, la saisie assumée (case non cochée par défaut), l'e-mail réellement reçu, l'application par l'événement natif, le silence après refus/fermeture.

**Ce qu'on ne montre pas.** Le contenu de `ProactiveGuard` ou du code — si la question technique vient, elle se répond en une phrase (§5), pas par un écran de code.

**Si la question juridique tombe ici** (le moment le plus probable) : voir §5, réponse préparée.
